# Epic USCDI-Eligible APIs (extracted 2026-08-30)

The set Epic marks `data-uscdi-readonly="True"` on the app registration form, i.e. the APIs
an app may select while remaining eligible for Automatic Client Distribution.

**This is a snapshot, not an authority.** Epic changes the set — it moved to USCDI v3 in
2025. Re-extract from the form rather than trusting this file; see
[`epic-app-registration-checklist.md`](./epic-app-registration-checklist.md).

Recorded because Epic publishes no consolidated list: not in the patient-facing-apps
documentation, and the form's search box cannot filter by USCDI.

## Shape

| | Count |
|---|---:|
| Total entries | 247 |
| R4 | 165 |
| STU3 | 44 |
| DSTU2 | 37 |
| Other (`Introspect`) | 1 |
| **Distinct resources** | **32** |

247 entries across only 32 resources because each appears in up to three FHIR versions, as
both `.Read` and `.Search`, and across category variants (`Observation` alone has 42).

It is a genuine subset. Clinical-workflow variants visible in the picker — `CarePlan.Search
(Inpatient Pathway)`, `(Oncology)`, `(Outpatient)`, `(Patient Education)`, `(Questionnaires
Due)` — are all excluded; only Encounter, Longitudinal and Outside Record CarePlans qualify.

## Notes for this project

- **22 of the 23** resource types in `src/fhirSearchQueries.ts` have USCDI R4 coverage. The
  gap is `MedicationStatement`, which Epic does not offer in R4 at all — R4 uses
  `MedicationRequest`, which is already queried. Not a gap in practice.
- `Binary.Read/Search (Generated CDAs)` yields C-CDA documents, which `src/ccdaToEhr.ts`
  can already parse.
- The `Outside Record` variants return data the health system received from *other*
  organizations via Care Everywhere — directly useful for a longitudinal record.
- `ExplanationOfBenefit` **is** in the set, contrary to some third-party summaries.
